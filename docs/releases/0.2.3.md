# Gravewright 0.2.3 — Alpha

## Changes

Gravewright 0.2.3 adds public module support for importing card artwork and
translates the native controls attached to floating windows. These contracts
serve independent packages without putting their game rules into the core.

### Installer correction — October 14, 2026

- The native installer configures the official Marketplace automatically when
  no catalog is configured, including installations that previously declined it.
  Existing custom catalogs are preserved, and verified official settings can be
  reused offline. The separate Marketplace question has been removed.
- The frontend explicitly permits the installation script for the pinned
  `esbuild@0.28.2`, resolving the npm 11 script-approval warning. The policy
  authorizes this package only and participates in the frontend preparation cache.

### Installation-local storage correction — October 14, 2026

- All default data, logs, Runner/update state, managed tools, environments,
  caches and bootstrap temporary files stay in the extracted project folder.
  Runtime state uses `data/`; managed tools and caches use `data/runner/` on
  Windows, Linux and macOS.
- The installer no longer shares AppData, HOME or XDG state between copies.
  Foreign global active-release pointers are ignored, fixing startup failures
  reported as `Invalid active release path`. Legacy automatically generated
  global marketplace key paths are replaced with local official key files.
- The storage contract is documented in `AGENTS.md`, reinforced in code and
  covered by regression tests for multiple installations and stale global state.

The **0.2.3 ZIP and checksum have been reissued** with these corrections. Hosts
already on 0.2.3 should download the ZIP again, replace application files while
preserving `.env` and runtime data, and rerun the platform installer. The updater
does not propose another installation of the same version.

### Module and card support

- **Card image upload.** `host.call('card.asset.upload', {file, purpose})`
  accepts `card_front` and `card_back`, returning the native campaign asset ID.
  It reuses the native image validator, WebP conversion and failed-upload
  cleanup. The operation requires an active module lease and GM permission.
  Existing card definitions and deck instances can reuse the resulting assets.
- **Host calls from package contexts.** `context.host` is available during
  module lifecycle and Customize actions, using the same public operations,
  activation lifetime and native permissions as mounted blocks.
- **Translated window controls.** Reset layout, Minimize and Restore use the
  active host Translator catalog, including windows owned by modules. Language
  changes update these controls without changing authored text or window
  content. Removed windows release their language listeners.

The SDK remains **1.0.0**. The new upload operation and `context.host` are
available starting in VTT **0.2.3**; SDK compatibility alone does not promise
these capabilities in 0.2.2 installations. Independently installed systems
continue to own their sheets, item templates, deck artwork and rules.

Validation: 75 isolated Django tests for modules, native cards and release
archives passed (one existing platform-dependent skip); all 36 JavaScript
module tests passed; the standalone native-window browser scenario passed in
English, Portuguese and Spanish. Archive selection and release metadata checks
passed without reading production configuration or data.

### Download and upgrade

Use **Gravewright-0.2.3-django.zip** with its matching **.zip.sha256** file.
The complete archive contains the Windows, Linux and macOS installers. Hosts
on 0.2.1 or 0.2.2 can use **Administration → Updates → Check for updates**.
Back up configuration, the configured database and private media together.

For a manual update, stop the Runner, replace application files while keeping
`.env` and runtime data, and rerun the platform installer. A normal upgrade
preserves saved language preferences and uses the existing migration workflow.

This release introduces no database migrations or new runtime dependencies.
English remains the default interface language for installations without a
saved host or account preference. Translator language choices remain available.

The version identifier is `0.2.3` and the release tag is `v0.2.3`; the project
continues in the **Alpha** development stage.

## Português (Brasil)

O Gravewright 0.2.3 acrescenta suporte público para módulos importarem imagens
de cartas e traduz os controles nativos das janelas flutuantes. Esses contratos
atendem pacotes independentes sem colocar suas regras de jogo no core.

### Correção do instalador — 14 de outubro de 2026

- O instalador nativo configura automaticamente o Marketplace oficial quando
  não há catálogo configurado, incluindo instalações que recusaram a opção
  anteriormente. Catálogos personalizados são preservados, e configurações
  oficiais verificadas podem ser reutilizadas offline. A pergunta foi removida.
- O frontend autoriza explicitamente o script de instalação do
  `esbuild@0.28.2` fixado, corrigindo o aviso de aprovação de scripts do npm 11.
  A política autoriza somente esse pacote e integra o cache de preparação do frontend.

### Correção do armazenamento local — 14 de outubro de 2026

- Todos os dados, logs, estado do Runner/atualizador, ferramentas gerenciadas,
  ambientes, caches e arquivos temporários do bootstrap ficam por padrão dentro
  da pasta descompactada. O estado usa `data/`; ferramentas e caches usam
  `data/runner/` no Windows, Linux e macOS.
- O instalador deixa de compartilhar estado em AppData, HOME ou XDG entre cópias.
  Ponteiros globais de outras instalações são ignorados, corrigindo falhas de
  início com `Invalid active release path`. Caminhos globais de chaves do
  Marketplace gerados automaticamente são substituídos por chaves oficiais locais.
- A regra de armazenamento está no `AGENTS.md`, documentada no código e coberta
  por testes de instalações independentes com estado global antigo.

O **ZIP e o checksum da 0.2.3 foram reemitidos** com essas correções. Quem já usa
0.2.3 deve baixar o ZIP novamente, substituir os arquivos da aplicação preservando
`.env` e os dados de execução e rodar o instalador da plataforma. O atualizador
não oferece uma nova instalação da mesma versão.

### Suporte a módulos e cartas

- **Upload de imagens de cartas.** `host.call('card.asset.upload', {file, purpose})`
  aceita `card_front` e `card_back` e retorna o ID do recurso nativo da campanha.
  A operação reutiliza validação de imagens, conversão para WebP e limpeza de
  uploads que falharam. Exige contexto ativo do módulo e permissão de mestre.
  Definições de cartas e instâncias de baralho podem reutilizar esses recursos.
- **Chamadas do host nos contextos do pacote.** `context.host` fica disponível
  na inicialização do módulo e nas ações de Personalizar, com as mesmas
  operações públicas, duração de ativação e permissões dos blocos montados.
- **Controles de janela traduzidos.** Restaurar disposição, Minimizar e
  Restaurar usam o catálogo ativo do Translator do host, inclusive nas janelas
  dos módulos. A mudança de idioma atualiza os controles sem alterar textos
  escritos pelo usuário ou o conteúdo da janela. Janelas removidas liberam
  seus listeners de idioma.

O SDK continua em **1.0.0**. A operação de upload e `context.host` estão
disponíveis a partir do VTT **0.2.3**; a compatibilidade com o SDK não garante
essas capacidades em instalações da 0.2.2. Os sistemas instalados continuam
responsáveis por fichas, estruturas de itens, imagens de baralho e regras.

Validação: passaram 75 testes Django isolados de módulos, cartas nativas e
pacotes de release (um caso existente específico de plataforma foi pulado),
os 36 testes JavaScript de módulos e o cenário independente de janela nativa
em inglês, português e espanhol. A seleção do pacote e os metadados da versão
passaram sem ler a configuração ou os dados da instalação em uso.

### Download e atualização

Use **Gravewright-0.2.3-django.zip** com o arquivo **.zip.sha256** correspondente.
O pacote completo contém os instaladores Windows, Linux e macOS. Hosts na
0.2.1 ou 0.2.2 podem usar **Administração → Atualizações → Verificar atualizações**.
Faça backup conjunto da configuração, do banco configurado e da mídia privada.

Na atualização manual, pare o Runner, substitua os arquivos da aplicação
preservando `.env` e dados de execução e rode novamente o instalador da
plataforma. A atualização normal preserva os idiomas salvos e usa o fluxo
existente de migrações.

Esta versão não introduz migrações de banco nem dependências de execução.
Inglês continua como idioma padrão quando não há preferência salva da
instalação ou da conta. As opções de idioma do Translator continuam disponíveis.

O identificador da versão é `0.2.3` e a tag é `v0.2.3`; o projeto continua em
estágio de desenvolvimento **Alpha**.
