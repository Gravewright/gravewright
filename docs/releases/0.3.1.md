# Gravewright 0.3.1 — Alpha

## Changes

Gravewright 0.3.1 improves form presentation throughout the host and expands
Map Builder with an interactive object catalog, object menus and synchronization
of edits made in the game. These notes cover the changes since `v0.3.0`.

### Consistent forms and campaign images

- Native inputs, selects, upload buttons, checkboxes, sliders and color controls
  follow the dark host theme, including forms opened dynamically. Focus,
  disabled and invalid states use the existing design tokens; single-choice
  selects keep their chevrons. Host interface text stays at least 12px.
- Campaign creation and editing use the shared field styling and a responsive
  modal. The cover upload has a themed drop area, keyboard access, image preview
  and removal controls for both newly selected and previously saved images.
  Clicking the already selected image source preserves the current image.
  The operating system's file picker still opens when choosing a file.
- Account settings organize profile and password fields more clearly and
  associate the current-password instructions with the input. Administration,
  privacy, package installation, tabletop tools, journals, dice and the bundled
  PDF System receive matching field surfaces, spacing and narrow-screen fixes.
- Actor and folder creation use the existing application modal, with Cancel,
  keyboard focus and controls disabled while saving. Closing or changing access
  releases the modal through the same lifecycle as other native windows.

See [frontend form controls](../en/frontend.md#form-controls) for the shared
styling and accessibility conventions.

### Marketplace tags follow the selected language

- Marketplace tag badges and categories follow the selected Translator language
  in English, Portuguese (Brazil) and Spanish. Categories sort by their displayed
  labels, and searches in both the Marketplace and installed package library
  match original tags and their translated labels, for systems and modules.
- Translation changes display labels only. Signed catalog records, package IDs,
  raw tag values and category filters remain intact, as do authored package names,
  descriptions, acronyms and custom tags without a translation entry.
- Long tags wrap within their badges on narrow screens. Removing or remounting
  a package catalog releases its pending requests, language listeners and open
  package dialogs, restoring normal scrolling and interaction.

### Map Builder object menus and models

- Open an object's menu with a right click, **Shift+F10**, the context-menu key
  or the Selection panel's **Object options** control. It offers separate
  **Properties**, **Appearance** and **Behavior** windows, compatible component
  editors, **Edit nodes**, duplication, rotation and deletion.
- **Ready-made models**, the **Interactive object catalog** and the node editor's
  **Object catalog** share 14 editable generic behaviors: switches, chests,
  secret passages, books, altars, warning traps, bells, pressure plates, dice
  challenges, quest activation/completion, entrance signs, timed switches and
  door buttons. Search and configure a model before applying it.
- Models support optional campaign audio with volume and optional active-state
  Object artwork. Unchecked options add no sound or image override; the inactive
  state retains the original image. Applying a model preserves object identity
  and geometry, creates one undo step and confirms replacement of authored
  behavior in the application modal. The warning trap sends a warning; RPG
  damage and other system rules remain the responsibility of system packages.
- **Request dice roll** sends authorized recipients a native prompt. Each
  recipient explicitly chooses **Roll**, and the normal dice service validates
  and posts the result to chat with public or GM visibility. Retries and other
  tabs reuse the same logical roll identity for that recipient. Streamers do
  not receive roll prompts; the graph continues without waiting for a result.
- **Open journal** can target diaries, quests and quest boards without granting
  reading permission. **Set quest status** executes a fixed GM-authored quest
  action through the journal service; interacting players gain no general
  journal editing permission. Rehearsals report quest changes and roll prompts
  without saving quest changes or delivering player windows.

These additions use generic host capabilities and translated controls. They do
not bundle an RPG ruleset or third-party content. See the
[Map Builder guide](../en/map-builder.md) for authoring and permission limits.

### Bring game edits back into a project

- Opening a linked project, returning to its browser tab and updating its scene
  synchronize compatible manual VTT edits to generated objects. Names,
  geometry, artwork, lights, effects and Blueprints return to the editable
  project; deleting a generated object removes its corresponding source.
  Split wall spans can be edited independently. Objects added directly to the
  scene remain separate from the project.
- Changes to different properties merge with pending project edits, and Undo
  preserves imported game changes while reversing local work. Conflicting
  changes to the same property retain the local draft and offer explicit reload
  or copy recovery. Unsupported object-type or geometry changes report a
  conflict instead of silently replacing work.
- Synchronization checks campaign ownership and both project and scene revisions.
  It imports authoring changes without executing behaviors or broadcasting a
  scene. Generating or updating the scene remains an explicit GM operation;
  runtime door states and other supported live state keep their existing rules.
- Generation history and campaign archive handling retain the synchronization
  baseline, supported native presentation overrides, quest bindings and authored
  roll expressions/labels. Audio omission and resource deletion also reconcile
  the retained source documents.

See [updating a generated scene](../en/map-builder.md) for conflict recovery and
the boundaries between project authoring and live play.

### Compatibility, migrations and data

There are **no new database migrations relative to 0.3.0**. Run the normal
migration workflow when installing or upgrading, especially from older versions;
the [0.3.0 notes](0.3.0.md#compatibility-migrations-and-data) describe the six
Map Builder migrations introduced in that release.

The browser SDK remains **1.0.0** and public module contract versions are
unchanged. Existing RPG systems stay independent packages. The new Blueprint
actions require this host version; an SDK range does not make them available
on older hosts. Review backups before downgrading projects that use these actions
or the newer synchronization history.

Default configuration, database, media, managed environments, caches and update
state continue to belong to each extracted installation. Preserve `.env`,
`data/`, local extensions and any explicit operator storage paths. A campaign
ZIP is not a full installation backup: it does not include accounts, configuration
or pending automation jobs. Rollback needs matching code and data backups.

### Download and upgrade

Use **`Gravewright-0.3.1-django.zip`** and its matching
**`Gravewright-0.3.1-django.zip.sha256`** from tag **`v0.3.1`**. The complete ZIP
includes the Windows, Linux and macOS installers. For a new installation,
extract it into a writable folder, run the platform installer and then start
the generated Runner. Tool downloads require internet when compatible local
tools or cached packages are unavailable.

Managed installations on **0.3.0** can update normally to **0.3.1** through
**Administration → Updates → Check for updates**. Back up configuration and
configured data together before upgrading, and keep the Runner open during the
update. Automatic discovery requires the configured releases repository and a
release with a higher version number.

If you downloaded the incorrectly numbered **3.0.1** release, install **0.3.1**
manually. The updater compares version numbers and considers **3.0.1** higher
than **0.3.1**, so it will not automatically downgrade that installation.

For a manual upgrade, back up the installation, stop the Runner and other
application processes, and replace application files while preserving `.env`,
`data/`, `extensions/`, managed environments and explicit storage paths. Then
rerun the installer for that platform before starting the updated Runner. Source
installations must install locked dependencies and run migrations before starting
the updated server.

See the [Windows](../en/windows-runner.md), [Linux](../en/linux-runner.md),
[macOS](../en/macos-runner.md) and [deployment](../en/deployment.md) guides for
platform prerequisites, storage, backups and recovery. The project remains in
**Alpha**, with English as the default interface language and existing host
and account language choices preserved.

## Português (Brasil)

O Gravewright 0.3.1 melhora os formulários do host e amplia o Map Builder com
um catálogo de objetos interativos, menus de objetos e sincronização das edições
feitas na mesa. Estas notas reúnem as mudanças desde `v0.3.0`.

### Formulários consistentes e imagens de campanha

- Campos nativos, seletores, botões de upload, caixas de seleção, controles de
  faixa e de cor seguem o tema escuro do host, inclusive nos formulários abertos
  dinamicamente. Foco, campos desativados e erros usam os tokens visuais
  existentes; seletores de uma opção mantêm suas setas. O texto da interface
  do host permanece com pelo menos 12px.
- Criação e edição de campanhas usam os campos compartilhados e um modal
  responsivo. O upload de capa tem área visual para arrastar arquivos, acesso
  pelo teclado, prévia e remoção tanto da imagem recém-selecionada quanto da
  imagem já salva. Clicar novamente na origem de imagem selecionada preserva a
  imagem atual. A escolha do arquivo continua abrindo o seletor do sistema
  operacional.
- Configurações de conta organizam melhor perfil e senhas e associam as
  instruções da senha atual ao campo. Administração, privacidade, instalação
  de pacotes, ferramentas da mesa, diários, dados e PDF System integrado recebem
  campos, espaçamento e ajustes para telas estreitas coerentes com o tema.
- Criação de atores e pastas usa o modal existente da aplicação, com Cancelar,
  foco pelo teclado e controles desativados durante o salvamento. Fechamento ou
  mudança de acesso libera o modal pelo mesmo ciclo das demais janelas nativas.

Veja [controles de formulário do frontend](../pt-BR/frontend.md#controles-de-formulário)
para as convenções compartilhadas de estilo e acessibilidade.

### Tags do Marketplace seguem o idioma selecionado

- Badges de tags e categorias do Marketplace seguem o idioma selecionado no
  Translator em inglês, português do Brasil e espanhol. As categorias são
  ordenadas pelos rótulos exibidos, e a busca no Marketplace e na biblioteca de
  pacotes instalados encontra tanto as tags originais quanto seus rótulos
  traduzidos, para sistemas e módulos.
- A tradução altera apenas os rótulos exibidos. Registros assinados do catálogo,
  IDs dos pacotes, valores originais das tags e filtros de categoria permanecem
  intactos, assim como nomes e descrições criados pelos autores, siglas e tags
  personalizadas sem uma entrada de tradução.
- Tags longas quebram dentro dos próprios badges em telas estreitas. Remover ou
  remontar um catálogo libera requisições pendentes, listeners de idioma e
  janelas de pacote abertas, restaurando a rolagem e a interação normais.

### Menus e modelos de objetos do Map Builder

- Abra o menu do objeto com o botão direito, **Shift+F10**, a tecla de menu de
  contexto ou **Opções do objeto** no painel Seleção. O menu oferece janelas
  separadas de **Propriedades**, **Aparência** e **Comportamento**, editores de
  componentes compatíveis, **Editar nós**, duplicação, rotação e exclusão.
- **Modelos prontos**, **Catálogo de objetos interativos** e **Catálogo de
  objetos** do editor de nós compartilham 14 comportamentos genéricos editáveis:
  interruptores, baús, passagens secretas, livros, altares, armadilhas de aviso,
  sinos, placas de pressão, desafios de dados, ativação/conclusão de missões,
  placas de entrada, interruptores temporizados e botões de porta. Busque e
  configure um modelo antes de aplicá-lo.
- Os modelos aceitam áudio opcional da campanha com volume e uma imagem de
  Objeto opcional para o estado ativo. Opções desmarcadas não acrescentam som nem
  substituição da imagem; o estado inativo mantém a imagem original. Aplicar um
  modelo preserva identidade e geometria, cria uma etapa de Desfazer e confirma
  no modal da aplicação a substituição de um comportamento já criado. A
  armadilha envia um aviso; dano e outras regras de RPG continuam nos pacotes
  de sistema.
- **Solicitar rolagem de dados** envia uma janela nativa aos destinatários
  autorizados. Cada pessoa escolhe **Rolar**, e o serviço normal de dados valida
  e publica o resultado no chat, de forma pública ou para o mestre. Repetições
  e outras abas usam a mesma identidade de rolagem para aquele destinatário.
  Transmissores não recebem pedidos de rolagem; o grafo continua sem esperar
  o resultado.
- **Abrir diário** pode apontar para diários, missões e quadros de missões sem
  conceder permissão de leitura. **Definir status da missão** executa uma ação
  fixa criada pelo mestre pelo serviço de diários; jogadores que interagem não
  ganham permissão geral de edição. Ensaios mostram mudanças de missão e pedidos
  de rolagem sem salvar essas mudanças nem abrir janelas para os jogadores.

Essas adições usam capacidades genéricas do host e controles traduzidos. Não
incluem regras de RPG nem conteúdo de terceiros. Veja o
[guia do Map Builder](../pt-BR/map-builder.md) para criação e limites de permissão.

### Trazer edições da mesa para o projeto

- Abrir um projeto vinculado, voltar à sua aba e atualizar a cena sincroniza
  edições manuais compatíveis dos objetos gerados no VTT. Nomes, geometria,
  imagens, luzes, efeitos e Blueprints retornam ao projeto editável; excluir
  um objeto gerado remove sua origem correspondente. Trechos divididos de
  parede podem ser editados separadamente. Objetos acrescentados diretamente
  à cena permanecem separados do projeto.
- Mudanças em propriedades diferentes são combinadas com edições pendentes do
  projeto, e Desfazer mantém as mudanças importadas da mesa ao reverter trabalho
  local. Alterações conflitantes na mesma propriedade preservam o rascunho local
  e oferecem recuperação explícita por recarga ou cópia. Mudanças incompatíveis
  de tipo ou geometria apresentam um conflito em vez de substituir trabalho
  silenciosamente.
- A sincronização verifica a campanha e as revisões do projeto e da cena.
  Importa alterações de criação sem executar comportamentos nem transmitir
  uma cena. Gerar ou atualizar a cena continua sendo uma operação explícita do
  mestre; estados de portas e outros estados de jogo compatíveis mantêm as
  regras existentes.
- O histórico de geração e os arquivos de campanha preservam a base de
  sincronização, substituições nativas compatíveis de apresentação, vínculos
  de missões e expressões/rótulos de dados criados pelo autor. Omissão de áudio
  e exclusão de recursos também reconciliam os documentos de origem retidos.

Veja [atualização de cena gerada](../pt-BR/map-builder.md) para recuperação de
conflitos e limites entre criação do projeto e uso na mesa.

### Compatibilidade, migrações e dados

Não há **novas migrações de banco em relação à 0.3.0**. Execute o fluxo normal
de migrações na instalação ou atualização, especialmente a partir de versões
anteriores; as [notas da 0.3.0](0.3.0.md#compatibilidade-migrações-e-dados)
descrevem as seis migrações do Map Builder introduzidas naquela release.

O SDK de navegador permanece **1.0.0** e as versões dos contratos públicos de
módulos não mudam. Sistemas de RPG existentes continuam em pacotes independentes.
As novas ações Blueprint exigem esta versão do host; uma faixa de SDK não as
disponibiliza em hosts antigos. Confira os backups antes de voltar projetos
que usam essas ações ou o novo histórico de sincronização para código anterior.

Configuração, banco, mídias, ambientes gerenciados, caches e estado de atualização
continuam pertencendo a cada instalação extraída. Preserve `.env`, `data/`,
extensões locais e caminhos explicitamente configurados. Um ZIP de campanha não
é um backup completo da instalação: não inclui contas, configuração nem tarefas
de automação pendentes. A reversão exige cópias compatíveis de código e dados.

### Download e atualização

Use **`Gravewright-0.3.1-django.zip`** e seu arquivo correspondente
**`Gravewright-0.3.1-django.zip.sha256`**, da tag **`v0.3.1`**. O ZIP completo
inclui instaladores para Windows, Linux e macOS. Para instalar do zero, extraia
em uma pasta gravável, execute o instalador da plataforma e depois inicie o
Runner gerado. Downloads precisam de internet quando não há ferramentas locais
compatíveis ou pacotes no cache.

Instalações gerenciadas na **0.3.0** podem atualizar normalmente para **0.3.1** em
**Administração → Atualizações → Verificar atualizações**. Faça backup conjunto
da configuração e dos dados configurados antes de atualizar e mantenha o Runner
aberto durante o processo. A descoberta automática exige um repositório de
releases configurado e uma release com número de versão maior.

Se você baixou a release numerada incorretamente como **3.0.1**, instale a
**0.3.1 manualmente**. O atualizador compara números de versão e considera
**3.0.1** maior que **0.3.1**, portanto não fará esse downgrade automaticamente.

Na atualização manual, faça backup da instalação, pare o Runner e os demais
processos da aplicação e substitua os arquivos da aplicação preservando `.env`,
`data/`, `extensions/`, ambientes gerenciados e caminhos explícitos. Depois,
execute novamente o instalador da plataforma antes de iniciar o Runner
atualizado. Instalações pelo código-fonte precisam instalar as dependências
fixadas e executar migrações antes de iniciar o servidor atualizado.

Veja os guias de [Windows](../pt-BR/windows-runner.md),
[Linux](../pt-BR/linux-runner.md), [macOS](../pt-BR/macos-runner.md) e
[implantação](../pt-BR/deployment.md) para requisitos, armazenamento, backups
e recuperação. O projeto continua em **Alpha**, com inglês como idioma padrão
e as escolhas de idioma existentes do host e das contas preservadas.
