# Gravewright 0.3.3 — Alpha

## Changes

Gravewright 0.3.3 improves scene audiences, token presentation and MapBuilder
authoring, and lets Smart Objects control shader parameters. These notes cover
the changes since `0.3.2`.

### Scenes and table preferences

- **Empty map** creates a scene from its name, background color and pixel
  dimensions, with controls to show the grid and activate the scene on creation.
- GMs can activate a scene for selected players. The scene directory shows
  player dots in their identification colors and a **GM** badge for the GM's
  current scene. Activating for everyone clears individual destinations.
- Shared mouse pointers use each sender's ping color, follow scene coordinates
  through pan and zoom, and remain visible while stationary. Preferences have
  independent controls for displaying other pointers and sharing one's own.
  Positions are transient and restricted to authorized viewers of that scene.
- **Keyboard shortcuts** maps the table's supported tools and windows, with
  conflict checks and a restore-defaults action. Settings are per profile/device.
- **Title** adds authored text alongside a local measurement's dimensions.
  Measurements and their titles remain local to the browser session. The
  separate Shapes tool is removed; drawing remains available through Mini Paint.
- Table descriptions show a live character counter. Ping colors and native
  translated controls include the corresponding fixes and reviewed translations.

### Token presentation

- Names, fallback initials and condition text remain sharp across zoom levels.
  The fixed decorative gold outline is removed.
- Bar 1 sits 5px above the token and bar 2 sits 5px below it. GMs can configure
  each bar's color and audience: everyone, owner and GM, or GM only. The server
  filters restricted bars before delivery. Numerical bar labels are not added.
- Token settings provide name display on selection, hover, both or always, and
  an optional current/next-turn outline. Appearance settings survive duplication
  and remain independent of the RPG system's sheet schema.

### MapBuilder and Smart Objects

- Uploaded object artwork can open a blank Smart Object Blueprint through
  **Edit nodes**, **Smart object**, or a left-button double-click with Selection
  or Objects active. Existing artwork, geometry and behavior are preserved.
- Objects can have circular activation areas independent of their artwork.
  Connect enter/exit events to effects without requiring a click. The area guide
  follows the object and is visible only to GMs in the editor.
- **Builder tools** adds grouping into layers, alignment, distribution and group
  rotation. **My objects** saves reusable campaign models with their artwork,
  component links, activation areas and behavior graphs.
- **Object brush** paints repeated objects with spacing and size/rotation
  variation. Each stroke is one Undo step. An area overview displays object and
  region guides while respecting layer visibility and isolation.
- **Test as player** opens a detached rehearsal with movement, collision,
  visibility, interaction and area events. Server behavior tests roll back their
  changes. Rehearsal does not broadcast effects or modify the live scene, and
  does not simulate system-specific rules or advance timers.
- The **Control shader** Blueprint node changes enabled state, color, intensity,
  opacity, speed, scale, radius, rotation, light response and emission. Values
  can be fixed or connected through typed variable inputs and are validated on
  the server. Independent shaders and composed torch components are supported.
- Shader targets follow copies, templates and generated scene identities. Torch
  visibility still gates its component shader. Updating a scene preserves live
  shader values when the corresponding Builder parameter has not been edited.

See [MapBuilder](../en/map-builder.md) and the [frontend guide](../en/frontend.md).
The public SDK remains **1.0.0**; newer capabilities require a host that implements
them. Translator **0.1.4** includes the corresponding English, Portuguese and
Spanish interface catalogs. Authored names and titles retain their wording.

### Compatibility and migrations

There are **three new database migrations relative to 0.3.2**:

| App | Migration | Stored data |
| --- | --- | --- |
| `gravewright_maps` | `0014_sceneassignment` | Individual player scene destinations |
| `gravewright_maps` | `0015_builderobjectpreset` | Reusable campaign object models |
| `gravewright_tokens` | `0002_token_appearance` | Token presentation settings |

Apply all pending migrations when upgrading from an older version. Default
storage remains inside the installation; preserve `.env`, `data/`, `extensions/`
and explicitly configured storage paths. A campaign export is not a full
installation backup. Recovery requires compatible code and data from one backup.

### Download and upgrade

The release identifiers are **`v0.3.3`**, **`Gravewright-0.3.3-django.zip`** and
**`Gravewright-0.3.3-django.zip.sha256`**. Verify the checksum and extract the
complete ZIP into a writable folder. All three platform installers are included.

Back up configuration, database, private media and local extensions together.
Managed installations use **Administration → Updates → Check for updates**;
keep the Runner open during the update. For a manual upgrade, stop application
processes, replace application files while preserving local storage, and rerun
the platform installer before starting the Runner. Source installations run:

```bash
uv sync --locked
uv run --locked python manage.py migrate
uv run --locked python manage.py check
```

Version `0.3.3` is greater than `0.3.2`. Installations reporting the historical,
incorrectly numbered `3.0.1` need a manual installation or migration verified on
a disposable backup copy; do not force a database downgrade. Reinstalling the
same version also requires the manual procedure because updates compare versions.
See [upgrade and recovery](../en/upgrading.md).

## Português (Brasil)

O Gravewright 0.3.3 melhora a distribuição de cenas, a apresentação dos tokens e
a criação no MapBuilder, além de permitir que Objetos Inteligentes controlem
parâmetros de shaders. Estas notas cobrem as mudanças desde a `0.3.2`.

### Cenas e preferências da mesa

- **Mapa vazio** cria uma cena com nome, cor de fundo e dimensões em pixels,
  com opções de mostrar o grid e ativar a cena após a criação.
- Mestres podem ativar cenas para jogadores selecionados. A lista mostra
  bolinhas nas cores de identificação e o indicador **GM** na cena atual do
  mestre. Ativar para todos limpa os destinos individuais.
- Ponteiros compartilhados usam a cor do ping de cada pessoa, acompanham o mapa
  durante movimentos da câmera e zoom e continuam visíveis quando parados.
  Preferências permitem exibir os ponteiros e compartilhar o próprio de forma
  independente. Posições são temporárias e restritas a quem pode ver a cena.
- **Atalhos de teclado** configura as ferramentas e janelas disponíveis na mesa,
  com verificação de conflitos e restauração dos padrões, por perfil/dispositivo.
- **Título** acrescenta texto autoral às dimensões de uma medição local.
  Medições e títulos permanecem na sessão local do navegador. A ferramenta
  separada de formas foi removida; o desenho continua disponível no Mini Paint.
- Descrições de mesas mostram um contador de caracteres em tempo real. Cores
  dos pings e controles traduzidos incluem as correções e traduções revisadas.

### Apresentação dos tokens

- Nomes, iniciais e condições ficam nítidos nos diferentes níveis de zoom.
  O contorno dourado decorativo fixo foi removido.
- A barra 1 fica 5px acima do token e a barra 2 fica 5px abaixo. O mestre pode
  definir a cor e o público de cada barra: todos, dono e mestre ou somente
  mestre. O servidor filtra barras restritas antes do envio. Não foram
  acrescentados valores numéricos às barras.
- As configurações permitem mostrar nomes na seleção, ao passar o mouse, em
  ambos os casos ou sempre, além de um contorno opcional para o turno atual e o
  próximo. A aparência acompanha duplicações sem alterar a ficha do sistema.

### MapBuilder e Objetos Inteligentes

- Imagens de objetos enviadas podem abrir um Blueprint vazio por **Editar nós**,
  **Objeto inteligente** ou dois cliques com o botão esquerdo usando Seleção ou
  Objetos. A arte, geometria e o comportamento existente são preservados.
- Objetos podem ter áreas circulares de ativação independentes da imagem.
  Eventos de entrada/saída ativam efeitos sem exigir clique. A guia acompanha
  o objeto e aparece somente para mestres no editor.
- **Ferramentas do Builder** oferece agrupamento em camadas, alinhamento,
  distribuição e rotação de grupos. **Meus objetos** salva modelos da campanha
  com arte, componentes, áreas de ativação e grafos de comportamento.
- O **Pincel de objetos** pinta objetos repetidos com espaçamento e variação de
  tamanho/rotação. Cada traço ocupa uma etapa de Desfazer. A visão geral de áreas
  mostra guias de objetos e regiões respeitando visibilidade e isolamento.
- **Testar como jogador** abre um ensaio separado com movimento, colisão, visão,
  interação e eventos de área. Testes de comportamento no servidor revertem suas
  alterações. O ensaio não envia efeitos aos jogadores nem altera a cena real,
  não simula regras de sistemas e não avança temporizadores.
- O nó **Controlar shader** altera ativação, cor, intensidade, opacidade,
  velocidade, escala, raio, rotação, resposta e emissão de luz. Valores podem ser
  fixos ou conectados por entradas tipadas e são validados no servidor. Funciona
  com shaders independentes e componentes de tochas.
- Referências a shaders acompanham cópias, modelos e IDs das cenas geradas.
  A visibilidade da tocha continua controlando seu shader. Atualizar a cena
  preserva valores em execução quando o parâmetro correspondente não foi
  alterado no Builder.

Veja [MapBuilder](../pt-BR/map-builder.md) e o [guia de frontend](../pt-BR/frontend.md).
O SDK público permanece na **1.0.0**; capacidades novas exigem uma versão do host
que as implemente. O Translator **0.1.4** inclui os catálogos correspondentes em
inglês, português e espanhol. Nomes e títulos autorais preservam sua redação.

### Compatibilidade e migrações

São **três novas migrações de banco em relação à 0.3.2**:

| App | Migração | Dados armazenados |
| --- | --- | --- |
| `gravewright_maps` | `0014_sceneassignment` | Destinos individuais dos jogadores nas cenas |
| `gravewright_maps` | `0015_builderobjectpreset` | Modelos reutilizáveis de objetos da campanha |
| `gravewright_tokens` | `0002_token_appearance` | Configurações de apresentação dos tokens |

Aplique todas as migrações pendentes ao atualizar uma versão anterior. O
armazenamento padrão continua dentro da instalação; preserve `.env`, `data/`,
`extensions/` e caminhos configurados explicitamente. Uma exportação de campanha
não substitui um backup completo. Recuperação exige código e dados compatíveis
do mesmo backup.

### Download e atualização

Os identificadores são **`v0.3.3`**, **`Gravewright-0.3.3-django.zip`** e
**`Gravewright-0.3.3-django.zip.sha256`**. Confira o checksum e extraia o ZIP
completo em uma pasta gravável. Os três instaladores de plataforma estão incluídos.

Faça backup conjunto da configuração, banco, mídias privadas e extensões locais.
Instalações gerenciadas usam **Administração → Atualizações → Verificar
atualizações**; mantenha o Runner aberto durante o processo. Na atualização
manual, pare os processos, substitua os arquivos da aplicação preservando os
dados locais e execute novamente o instalador antes de iniciar o Runner.
Instalações pelo código executam os comandos `uv` mostrados acima.

A `0.3.3` é maior que a `0.3.2`. Instalações com a antiga `3.0.1`, numerada
incorretamente, precisam de instalação ou migração manual validada em uma cópia
descartável do backup; não force a redução do banco. Reinstalar a mesma versão
também exige o procedimento manual, pois o atualizador compara versões.
Veja [atualização e recuperação](../pt-BR/upgrading.md).
