# Gravewright 0.1.2

Gravewright remains an early development preview. Version 0.1.2 is published on
the stable update channel because its version identifier has no prerelease suffix.

## Changes

- Install trusted Django apps from signed marketplace catalogs or local ZIPs.
  Django packages appear in Modules with a **Django · Server** badge. Activation
  prepares an isolated Python environment, installs pinned dependencies without
  replacing locked core dependencies, checks Django, applies migrations, collects
  static files and restarts the server. Failed activation restores the previous
  package selection, Python environment and data.
- Preserve enabled Django packages and their dependencies across core updates.
  Python sources are kept out of browser package routes and table-level activation.
- Separate **Install Windows.bat** from the generated **Gravewright Runner.bat**.
  The installer prepares tools and dependencies, asks for personal settings and
  offers the default marketplace. The generated runner starts the application.
  Python 3.14 x64 installation uses the supported uv interpreter identifier.
- Replace project files during updates, including the installer and scripts,
  remove obsolete code, and regenerate the Windows launcher. Preserve personal
  settings and persistent storage. Optionally retain a sibling `.old` directory
  containing the previous code and matching data snapshots for manual rollback.
- Handle long Windows paths in module backups and restoration, and verify nested
  installed package paths consistently on Windows, Linux and macOS.
- Rebuild and validate committed frontend assets and update the installation,
  extension, deployment and testing documentation. Fix Windows test portability
  for shader fixture line endings and archive file handles, and update the
  development-server test for the explicit `--dev` mode.

## Download and install

Download **Gravewright-0.1.2-django.zip** and its matching **.sha256** file.
The ZIP contains the source, migrations, frontend assets, documentation, licenses
and Windows installer. It excludes generated launchers, environments, credentials,
user data and installed third-party modules. Missing tools and dependencies need
internet access; this is a source distribution rather than an offline installer.

On Windows, extract the entire ZIP, run **Install Windows.bat**, answer the
configuration questions, then start the generated **Gravewright Runner.bat**.
Supported Windows installations use x64 Windows 10 version 1803 or newer, or
Windows 11. Terminal installations require Python 3.14 or newer and uv; follow
the [getting-started guide](../en/getting-started.md).

Existing managed installations can select **Administration → Updates → Install
update**. Keep **Keep a .old copy for rollback** selected to retain a manual
rollback snapshot. Older installations without the update supervisor need a
manual launcher upgrade first. See [deployment and rollback](../en/deployment.md).

**Upgrading from the published 0.1.1 package:** its original supervisor can load
the new server from Administration, but keeps running the old launcher and does
not support Django activation jobs or the new file replacement workflow. After
the in-app update, stop the old Runner, extract the 0.1.2 ZIP over the original
project folder and run **Install Windows.bat**, keeping the same personal data
directory. Start the newly generated Runner. This one-time launcher replacement
enables the new supervisor; subsequent updates use the new replacement workflow.
Do not delete the personal data or its `updates` directory during this transition.

## Django package format

Catalog records must declare `"type": "django"`; ZIP manifests declare a `django`
block with app import paths and optional exact dependency pins. Browser modules
retain their existing format. Activation requires the managed Runner or `main.py`
and uv. Deactivation restarts without the app and preserves its database data.
See the [module guide](../en/modules.md#explicitly-installed-django-apps).

## Validation

- Django configuration and application test suite.
- JavaScript model, module lifecycle and shader tests on Node.js 24.
- Native Windows installer, private Python installation, offline reuse,
  configuration prompts, generated launcher and shortcut checks.
- Real Django package activation, routes, dependency constraints, migrations,
  failed-migration rollback and deactivation.
- Managed upgrade acceptance checks covering file replacement, launcher updates,
  preserved Django apps, migration/startup failures and manual `.old` restoration.
- Locked Python metadata, frontend build and release archive integrity checks.
