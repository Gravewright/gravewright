# Gravewright 0.3.8 — Alpha

## Initiative in one operation

- Add `combat.rollInitiativeBatch` for system packages to submit up to 64 prepared dice expressions in one request. The server validates every source revision before rolling, updates the order once and publishes at most two chat messages grouped by audience.
- Save initiative, chat messages and a dedicated operation receipt in one transaction. Retrying the same UUID and payload returns the accepted results and current combat state without rolling again. Current access is checked on every retry.
- Keep hidden participants and restricted direct actors out of public chat. Selecting the first participant is optional and does not start combat, advance rounds or tick effects.
- Keep RPG rules and formula preparation in their system package. Packages can detect the new method and retain their existing path on older hosts; the current individual initiative methods remain available. See the [API contract](../en/api.md).

Local browser validation with the D&D package and 20 participants measured
947.9, 924.7 and 883.3 ms from clicking Roll all until the order, current
participant and 20 audited chat results were visible to both GM and player,
with the GM controls available again. The median was **924.7 ms**. The three
real d20 batches ran with a 0.5-second interval and no quota or HTTP errors.
These are three local samples, not a latency guarantee for other devices,
networks or campaigns.

## Personal dock, shared measurements and drawings

- Open **Table settings → Preferences → Customize the dock** to reorder tools and panels, show or hide tools, and pin panels to the dock or keep them in the Panels menu. Restore defaults without changing keyboard shortcuts.
- Save the layout separately for each profile and campaign on this device and synchronize it across browser tabs. Personal customization preserves native permissions and control availability.
- Share completed ruler paths, area measurements and optional titles with authorized viewers of the scene. Measurements persist with the campaign; their titles follow movement and zoom and remain visible after closing the tool.
- Let players edit their own measurements and GMs edit all measurements. Measurements created in the GM workspace stay private to GMs; streamers receive public measurements with read-only access.
- Apply edits by marker revision so unrelated participants' work is preserved. Conflicting edits refresh the scene and report an error. Existing marker replacement callers retain their scene revision checks and preserve measurements they cannot see.
- Let players draw with Mini Paint (**Draw**, shortcut `B`) under the same rules: drawings on the Game layer reach everyone viewing the scene, and GM-layer drawings stay private to GMs. Streamers remain read-only.
- Record each drawing's author and revision on the server. Players erase, move, restyle and clear only their own drawings (**Clear my drawings**); GMs edit every drawing. Participants can draw at the same time, and undo restores only the author's own drawings.

## Compendium folders

- System packages can declare an optional `folder` path on each compendium collection. The **Compendiums** panel shows those packs inside collapsible folders, closed by default, and lists each pack by its own label inside the folder. Packs created in the table stay at the top level.
- Searches, type filters and the compendium selector open the folders that contain matches; clearing them restores the folders each member had open.
- GMs set player and streamer access for a whole folder through its **⋯** button. The change reaches every compendium in the folder and its subfolders in one operation, and roles left at **No change** keep each compendium's access. The compendium permissions dialog also reads access granted through the role command for installed packages correctly, so bulk changes preserve it.
- Folders change only the presentation. Pack IDs, read permissions, imports and actor import folders are unchanged, and earlier hosts ignore the field. See [Modules](../en/modules.md#compendiums-supplied-by-a-system-package).

## Compatibility and migration

This release adds `gravewright_combat.0002_initiativebatchreceipt`, a table for
private initiative operation receipts. Existing encounters, sheets and scene
markers are preserved. Run the normal installer migration workflow before
starting the updated server. The SDK version remains `1.0.0`; the new browser
method is additive and does not move system rules into the core.

Drawings saved before this release have no recorded author, so only GMs can edit
them. The GM-only whole-document drawing replacement remains available and keeps
each drawing's author and revision.

Dock preferences are local to the browser; changing them does not broadcast a
layout to other participants. Shared scene edits continue through the existing
authorized projections. Measurement broadcasts publish completed changes, not a
continuous pointer stream.

## Português (Brasil)

### Iniciativa em uma operação

- Acrescenta `combat.rollInitiativeBatch` para pacotes de sistema enviarem até 64 expressões de dados preparadas em uma requisição. O servidor valida todas as revisões de origem antes de rolar, atualiza a ordem uma vez e publica no máximo duas mensagens de chat, agrupadas por público.
- Grava iniciativa, mensagens e um recibo próprio da operação em uma transação. Repetir o mesmo UUID e payload devolve os resultados aceitos e o estado atual do combate sem rolar novamente. O acesso atual é verificado em cada repetição.
- Mantém participantes ocultos e atores diretos com acesso restrito fora do chat público. Selecionar o primeiro participante é opcional e não inicia combate, avança rodadas nem processa efeitos.
- Mantém regras de RPG e preparação das fórmulas no pacote de sistema. Pacotes podem detectar o novo método e preservar seu fluxo existente em hosts anteriores; os métodos individuais de iniciativa continuam disponíveis. Consulte o [contrato da API](../pt-BR/api.md).

Uma validação local no navegador, com o pacote de D&D e 20 participantes,
mediu 947,9, 924,7 e 883,3 ms entre clicar em Rolar todos e exibir a ordem,
o participante atual e os 20 resultados auditados no chat para mestre e jogador,
com os controles do mestre novamente disponíveis. A mediana foi **924,7 ms**.
Os três lotes reais de d20 foram executados com intervalo de 0,5 segundo, sem
erros de limite de mensagens ou HTTP. São três amostras locais, sem garantia
de latência para outros dispositivos, redes ou campanhas.

### Dock pessoal, medições e desenhos compartilhados

- Abra **Configurações da mesa → Preferências → Personalizar a dock** para reordenar ferramentas e painéis, mostrar ou ocultar ferramentas e fixar painéis na dock ou mantê-los no menu Painéis. Restaure o padrão sem alterar os atalhos de teclado.
- Salva a organização separadamente para cada perfil e campanha neste dispositivo e a sincroniza entre abas do navegador. A personalização preserva as permissões nativas e a disponibilidade dos controles.
- Compartilha caminhos concluídos da régua, medições de área e títulos opcionais com os espectadores autorizados da cena. As medições ficam salvas na campanha; seus títulos acompanham movimento e zoom e permanecem visíveis após fechar a ferramenta.
- Permite que jogadores editem suas próprias medições e mestres editem todas. Medições criadas no espaço do mestre ficam privadas para mestres; espectadores de transmissão recebem as medições públicas com acesso somente de leitura.
- Aplica edições pela revisão de cada marcador, preservando alterações de outros participantes. Conflitos atualizam a cena e mostram um erro. Chamadas existentes de substituição dos marcadores mantêm suas verificações da revisão da cena e preservam medições que não podem visualizar.
- Permite que jogadores desenhem com o Mini Paint (**Desenhar**, atalho `B`) com as mesmas regras: desenhos na aba Jogo chegam a todos que veem a cena, e desenhos na aba GM ficam privados para mestres. Streamers continuam somente leitura.
- Registra no servidor o autor e a revisão de cada desenho. Jogadores apagam, movem, alteram o estilo e limpam apenas os próprios desenhos (**Limpar meus desenhos**); mestres editam todos. Os participantes podem desenhar ao mesmo tempo, e desfazer restaura apenas os desenhos do próprio autor.

### Pastas de compêndios

- Pacotes de sistema podem declarar um caminho opcional `folder` em cada coleção de compêndios. O painel **Compêndios** mostra esses compêndios dentro de pastas recolhíveis, fechadas por padrão, e lista cada compêndio pelo próprio rótulo dentro da pasta. Compêndios criados na mesa continuam no nível principal.
- Buscas, filtros de tipo e o seletor de compêndio abrem as pastas que têm resultados; ao limpá-los, cada membro volta às pastas que tinha abertas.
- O mestre define o acesso de jogadores e transmissões a uma pasta inteira pelo botão **⋯** dela. A alteração chega a todos os compêndios da pasta e de suas subpastas em uma operação, e funções mantidas em **Não alterar** conservam o acesso de cada compêndio. O diálogo de permissões de compêndios também passa a ler corretamente o acesso concedido pelo comando por função em pacotes instalados, e as alterações em lote o preservam.
- As pastas mudam apenas a apresentação. IDs de compêndios, permissões de leitura, importações e as pastas de atores importados não mudam, e hosts anteriores ignoram o campo. Consulte [Módulos](../pt-BR/modules.md#compêndios-fornecidos-por-um-pacote-de-sistema).

### Compatibilidade e migração

Esta versão acrescenta `gravewright_combat.0002_initiativebatchreceipt`, uma tabela
de recibos privados das operações de iniciativa. Combates, fichas e marcadores
existentes são preservados. Execute o fluxo normal de migrações do instalador
antes de iniciar o servidor atualizado. A versão do SDK permanece em `1.0.0`;
o novo método do navegador é aditivo e mantém as regras de sistema fora do núcleo.

Desenhos salvos antes desta versão não têm autor registrado, então só mestres
podem editá-los. A substituição do documento inteiro de desenhos, exclusiva do
mestre, continua disponível e mantém o autor e a revisão de cada desenho.

As preferências da dock são locais ao navegador; alterá-las não transmite uma
organização para outros participantes. Edições compartilhadas da cena continuam
usando as projeções autorizadas existentes. O compartilhamento de medições
publica alterações concluídas, sem um fluxo contínuo do ponteiro.

## Download and upgrade

Download `Gravewright-0.3.8-django.zip` and verify its accompanying SHA-256 file.
Managed installations can use Administration → Updates. For a manual upgrade,
stop the Runner, back up and preserve `.env`, `data/` and local extensions,
replace application files and rerun the platform installer to prepare assets and
apply migrations. Restart the server and reload connected browser tabs. With
SQLite WAL enabled, stop all database users before copying database files or use
the application's backup tools; never discard an active database's `-wal` or
`-shm` files. See [upgrade and recovery](../en/upgrading.md).

## Download e atualização

Baixe `Gravewright-0.3.8-django.zip` e confira o SHA-256. Instalações gerenciadas
podem usar Administração → Atualizações. Na atualização manual, pare o Runner,
faça backup e preserve `.env`, `data/` e extensões locais, substitua os arquivos
da aplicação e execute novamente o instalador para preparar os recursos e aplicar
as migrações. Reinicie o servidor e recarregue as abas conectadas. Com WAL ativo
no SQLite, pare todos os processos que usam o banco antes de copiar seus arquivos
ou utilize as ferramentas de backup da aplicação; nunca descarte os arquivos
`-wal` ou `-shm` de um banco ativo. Veja [atualização e recuperação](../pt-BR/upgrading.md).
