# Gravewright 0.2.2 — Alpha

**13 October 2026**

Gravewright 0.2.2 improves release discovery, the Administration screen and
Marketplace installation. It also fixes opening forms cloned from templates,
including scene creation. Gravewright remains a universal, self-hosted VTT in
Alpha; game rules and content belong to separately installed systems.

## Changes

- **Release alerts.** The installation owner has a bell beside their name in
  the library header. A gold marker indicates a newer verified VTT release.
  The alert compares installed and available versions and opens Administration
  directly on Updates. Discovery uses the host's cache and never starts an
  installation automatically; participant accounts do not receive these alerts.
- **Clearer version information.** Administration → Updates highlights the
  full installed release name, such as **Gravewright 0.2.2 — Alpha**. The
  release-channel selector and its save controls have been removed from the
  screen. Existing channel preferences and update API compatibility are
  preserved; this change does not silently move hosts to a different channel.
- **Readable release notes, including offline.** The installed version's
  bundled notes are available immediately without an internet connection or a
  prior update check. Published notes and version history support headings,
  lists, code and safe links. A Portuguese interface selects the Brazilian
  Portuguese section when it exists. Notes are bounded to 128 KiB of UTF-8
  instead of the former 4,000-character truncation; older truncated cache
  entries can fall back to the complete bundled document.
- **Focused update controls.** A newer release displays its full name and
  notes with the installation controls. The rollback checkbox and progress
  information are aligned within a dedicated installation panel. The screen
  adapts to narrow displays and keeps installation an explicit owner action.
- **Latest compatible Marketplace packages.** Systems and Modules show only
  the highest compatible, non-revoked release of each package when installing.
  Search, filters and pagination use that selection. Signature and revocation
  validation still apply to the full catalog. The default Marketplace API and
  exact-version installation remain available for integrations.
- **Modal form fix.** Shared modals correctly attach forms cloned from HTML
  templates before opening them. Scene creation no longer fails with
  `Cannot read properties of null (reading 'children')`. Focus, Escape and
  closing behavior remain part of the shared modal lifecycle.

See the [user guide](../en/user-guide.md), [API guide](../en/api.md) and
[testing guide](../en/testing.md) for the workflows and regression scenarios.

## Compatibility

The browser SDK remains **1.0.0**. The `system.combat`, `content.compendiums`
and shared module-modal saving capabilities introduced in VTT **0.2.1** keep
that minimum host version. No game-specific rules are added to the core.
Translator, third-party systems and their content are separate packages; the
DnD 5e SRD system is not bundled in the VTT archive.

The package retains the Windows, Linux and macOS installers introduced in the
refreshed 0.2.1 archive. Linux detects the distribution family and supports
x64/ARM64 with the documented libc/tool requirements. macOS supports Intel
and Apple Silicon on macOS 13.5+; Intel requires Apple's Command Line Tools
and SDK and may take longer on its first dependency build. See the
[Windows](../en/windows-runner.md), [Linux](../en/linux-runner.md) and
[macOS](../en/macos-runner.md) guides for requirements and storage paths.

## Download and upgrade

Use **Gravewright-0.2.2-django.zip** with its matching **.sha256** file. The
archive contains public application files, documentation and built frontend
assets; it excludes `.env`, local databases, private media, installed extensions
and machine-specific launchers.

Hosts running **0.2.1 can upgrade normally** through **Administration →
Updates → Check for updates → Install update**. Unlike the same-version
0.2.1 package refresh, 0.2.2 is a new numeric version and does not require a
manual reinstall solely to receive these changes. An explicit check refreshes
discovery immediately instead of waiting for its cache to expire.

Before upgrading, make a consistent backup of `.env`, the configured database,
private media, installed packages and persistent trust/configuration data.
The managed updater disconnects active tables, prepares dependencies, applies
any pending migrations and restarts the host. Keep the matching old code and
backup together for recovery; a campaign export is not a complete instance
backup. The optional retained `.old` copy does not replace that backup.

For a manual installation, stop the Runner, extract the complete package while
preserving configuration and data, and rerun the installer for the host platform
to regenerate its Runner. Operator-managed source deployments must install
locked dependencies, apply migrations and prepare their static assets before
restarting. See [deployment and backups](../en/deployment.md).

The version identifier is `0.2.2`, the release tag is `v0.2.2` and its numeric
identifier follows the existing `stable` discovery convention. **Alpha** is
the project's development stage, independent of that internal classification.

## Português (Brasil)

**13 de outubro de 2026**

O **Gravewright 0.2.2 — Alpha** melhora a descoberta de versões, a tela de
Administração e a instalação pelo Marketplace. Também corrige a abertura de
formulários clonados de templates, incluindo a criação de cenas. O Gravewright
continua sendo um VTT universal que você pode hospedar; regras e conteúdo
pertencem aos sistemas instalados separadamente.

### Alterações

- **Alertas de versão.** O proprietário da instalação tem um sino ao lado do
  nome no cabeçalho da biblioteca. Um marcador dourado indica uma versão nova
  e verificada do VTT. O alerta compara as versões instalada e disponível e
  abre Administração diretamente em Atualizações. A consulta usa o cache do
  host e nunca inicia a instalação automaticamente. Participantes não recebem
  esses alertas administrativos.
- **Informação de versão mais clara.** Administração → Atualizações destaca
  o nome completo da versão instalada, como **Gravewright 0.2.2 — Alpha**.
  O seletor de canal e seu botão de salvar foram removidos da tela. Preferências
  de canal existentes e compatibilidade da API são preservadas; a mudança não
  transfere instalações silenciosamente para outro canal.
- **Notas legíveis, inclusive offline.** As notas empacotadas da versão
  instalada aparecem imediatamente, sem internet nem verificação anterior.
  Notas publicadas e histórico apresentam títulos, listas, código e links
  seguros. A interface em português seleciona a seção em português brasileiro
  quando disponível. O limite passa de 4.000 caracteres para 128 KiB em UTF-8;
  entradas antigas de cache truncadas podem usar o documento completo local.
- **Controles de atualização organizados.** Uma versão nova apresenta seu
  nome completo e notas junto dos controles de instalação. A opção de manter
  cópia para rollback e o progresso ficam alinhados em um painel próprio.
  A tela se adapta a telas estreitas; instalar continua exigindo uma ação
  explícita do proprietário.
- **Marketplace com a versão compatível mais recente.** Ao instalar em
  Sistemas ou Módulos, aparece apenas a maior versão compatível e não revogada
  de cada pacote. Busca, filtros e paginação usam essa seleção. Assinaturas e
  revogações continuam verificadas no catálogo completo. A API padrão e a
  instalação de uma versão exata permanecem disponíveis para integrações.
- **Correção de formulários em modais.** A modal compartilhada vincula à
  página os formulários clonados de templates HTML antes de abri-los. Criar
  uma cena deixa de falhar com
  `Cannot read properties of null (reading 'children')`. Foco, Escape e
  fechamento continuam seguindo o ciclo de vida da modal compartilhada.

Veja o [guia de uso](../pt-BR/user-guide.md), a [API](../pt-BR/api.md) e os
[testes](../pt-BR/testing.md) para fluxos e cenários de regressão.

### Compatibilidade

O SDK de navegador permanece **1.0.0**. As capacidades `system.combat`,
`content.compendiums` e salvamento das modais de módulos introduzidas na
**0.2.1** mantêm essa versão mínima do host. O núcleo não recebe regras de
jogos específicos. Translator, sistemas e conteúdo de terceiros são pacotes
separados; o sistema DnD 5e SRD não está incluído no arquivo do VTT.

O pacote mantém os instaladores Windows, Linux e macOS incluídos no
reempacotamento da 0.2.1. Linux detecta a família da distribuição e atende
x64/ARM64 com os requisitos documentados de libc e ferramentas. macOS atende
Intel e Apple Silicon no macOS 13.5+; Intel exige Command Line Tools e SDK
da Apple e pode demorar mais no primeiro build de dependências. Os guias
[Windows](../pt-BR/windows-runner.md), [Linux](../pt-BR/linux-runner.md) e
[macOS](../pt-BR/macos-runner.md) apresentam requisitos e caminhos.

### Download e atualização

Use **Gravewright-0.2.2-django.zip** com seu **.sha256** correspondente. O
arquivo inclui aplicação pública, documentação e frontend compilado; exclui
`.env`, bancos locais, mídias privadas, extensões instaladas e launchers
específicos da máquina.

Hosts na **0.2.1 podem atualizar normalmente** por **Administração →
Atualizações → Verificar atualizações → Instalar atualização**. Diferentemente
do reempacotamento da mesma 0.2.1, a 0.2.2 é uma nova versão numérica e não
exige reinstalação manual apenas para receber essas mudanças. A verificação
explícita renova a consulta imediatamente, sem aguardar o cache expirar.

Antes de atualizar, faça backup consistente de `.env`, banco configurado,
mídias privadas, pacotes instalados e dados persistentes de configuração e
confiança. O atualizador gerenciado desconecta as mesas, prepara dependências,
aplica eventuais migrações pendentes e reinicia o host. Guarde código anterior
e backup correspondentes juntos para recuperação; exportar uma campanha não
é um backup completo da instalação. A cópia `.old` opcional não substitui
esse backup.

Na instalação manual, pare o Runner, extraia o pacote completo preservando
configuração e dados e execute novamente o instalador da plataforma para
regenerar o Runner. Implantações por código-fonte precisam instalar dependências
fixadas, aplicar migrações e preparar arquivos estáticos antes de reiniciar.
Consulte [implantação e backups](../pt-BR/deployment.md).

O identificador é `0.2.2`, a tag é `v0.2.2` e o número segue a convenção
existente `stable` da descoberta. **Alpha** é o estágio de desenvolvimento
do projeto, independente dessa classificação interna.
