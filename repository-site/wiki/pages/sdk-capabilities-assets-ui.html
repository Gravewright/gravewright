Capabilities: assets and UI

This page documents 15 capabilities individually. A capability is an API gate, not a privilege escalation: every operation remains subject to server-side authorization.

assets.library

Authority level: UI · Status: stable · Surfaces: manifest, frontend

What it authorizes

Read the campaign asset library (list uploaded files) through the SDK.

When to use it

Declare it when the manifest provides or loads exactly this type of asset.

What it does NOT authorize

It authorizes only declared assets at safe paths inside the package; it does not grant arbitrary filesystem or network access.

Declaring a capability does not elevate the user, bypass ownership, or switch context to another campaign.

Available methods

  • sdk.assets.list

User permission requirements

Requires campaign membership. The service returns or changes only content visible or editable by the current user.

Minimal example

"capabilities": ["assets.library"]

await sdk.assets.list(/* contract parameters */);

Possible errors

  • CAPABILITY_REQUIRED: capability missing or method gated

Security and visibility filtering

Yes. The backend projects the response according to campaign, role, ownership, resource visibility, and layer. An omitted resource may be hidden rather than nonexistent.

Lifecycle and teardown

No special teardown is required. Await asynchronous runtime operations and handle the possibility that the campaign or resource changes before completion.

Related capabilities

assets.import, assets.ui, assets.styles, assets.scripts, assets.pack, assets.images, assets.audio, assets.video, assets.maps, assets.icons

Do not use it this way: Do not use absolute paths, '..' traversal, remote URLs as a substitute for packaged assets, or a different asset type from the one declared.

ui.slots

Authority level: UI · Status: stable · Surfaces: manifest, frontend, doctor

What it authorizes

Mount package-owned UI into documented host slots with teardown.

When to use it

Declare it when package runtime calls one of the public APIs listed below.

What it does NOT authorize

The gate unlocks only those public APIs and preserves host-side context validation and authorization.

Declaring a capability does not elevate the user, bypass ownership, or switch context to another campaign.

Available methods

  • sdk.ui.slots.available
  • sdk.ui.slots.register

User permission requirements

The package must be installed, enabled, and active. Operations remain bounded by the current user's context and role.

Minimal example

"capabilities": ["ui.slots"]

await sdk.ui.slots.available(/* contract parameters */);
await sdk.ui.slots.register(/* contract parameters */);

Possible errors

  • CAPABILITY_REQUIRED: capability missing or method gated

Security and visibility filtering

It does not directly return game collections. Context and payload still must not be used to infer hidden data.

Lifecycle and teardown

Register once during setup. Remove package-owned listeners, observers, timers, and mounts during unmount or close; do not register again on every render.

Related capabilities

ui.applications, ui.presentations, ui.dragDrop

Do not use it this way: Do not replace the API with fetch calls to internal routes, private globals, or direct manipulation of the core DOM.
