Capabilities: automation, interactions, and flows

This page documents 20 capabilities individually. A capability is an API gate, not a privilege escalation: every operation remains subject to server-side authorization.

packages.inspect

Authority level: UI · Status: stable · Surfaces: manifest, backend, frontend, doctor

What it authorizes

Inspect public package metadata available in the current context.

When to use it

Declare it when package runtime calls one of the public APIs listed below.

What it does NOT authorize

The gate unlocks only those public APIs and preserves host-side context validation and authorization.

Declaring a capability does not elevate the user, bypass ownership, or switch context to another campaign.

Available methods

  • sdk.packages.get
  • sdk.packages.has

User permission requirements

The package must be installed, enabled, and active. Operations remain bounded by the current user's context and role.

Minimal example

"capabilities": ["packages.inspect"]

await sdk.packages.get(/* contract parameters */);
await sdk.packages.has(/* contract parameters */);

Possible errors

  • CAPABILITY_REQUIRED: capability missing or method gated
  • PERMISSION_DENIED: user or context lacks authority

Security and visibility filtering

It does not directly return game collections. Context and payload still must not be used to infer hidden data.

Lifecycle and teardown

No special teardown is required. Await asynchronous runtime operations and handle the possibility that the campaign or resource changes before completion.

Related capabilities

None directly.

Do not use it this way: Do not replace the API with fetch calls to internal routes, private globals, or direct manipulation of the core DOM.
